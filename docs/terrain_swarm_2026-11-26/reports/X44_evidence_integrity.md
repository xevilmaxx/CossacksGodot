- **Pass 1 — citation extraction:** regex `ev_[0-9a-f]{64}` over every `.md` in `docs/terrain_swarm_2026-11-26/spec/` and `reports/`; recorded `file:line` for each occurrence (PowerShell `Select-String`-equivalent Python scan). - **Pass 2 — live ledger read:** `core_session_show` + `core_evidence_show({detail:"summary"})` (1175 → 1184 → 1191 records; active target switched between workers).
- **Pass 3 — frozen comparison:** `core_evidence_export` to `%TEMP%\opencode\x44_ledger.json` (1191 records, `not_loaded:0`), then a deterministic id-set comparison against the citation set. Results: 288 match / 1 missing / 903 unused.
- **Pass 4 — targeted re-read:** `core_evidence_show({detail:"complete", evidence_id:…})` and `core_evidence_show({operation:"native_name_xrefs_list"})` for the missing id and every suspected coverage/subject anomaly; `core_evidence_browse`-equivalent field inspection (`coverage`, `params`, `result.text`) for the text-read ids.
- **Pass 5 — claim re-read:** each flagged `file:line` in spec/00 and the donor report was re-read against the exact ledger `subject`/`operation`/`coverage`, and adjacent ids on the same line were checked to eliminate false positives from multi-id rows.
- Principle applied: an id is never declared mismatched on one reading; a discrepancy is reported only after the spec/report line **and** the ledger record were re-read (CHARTER §4 "multiple passes on anomalies").
