## 1. What was built

`app/tools/t6_registry.py` is a stdlib-only aggregator (imports:
`argparse`, `json`, `re`, `shutil`, `sys`, `datetime`, `pathlib` —
`observed` from the import block). It:

1. reads `docs/t6/reports/*.md` and parses the ticket id (`ticket:` header,
   first `# T6-…` heading, then filename), the header `date:`/`updated:`
   field (fallback: file mtime), claim tables (observed/derived/inferred/
   UNVERIFIED label counts + evidence cells) and acceptance-criterion tables
   (PASS/FAIL/UNVERIFIED counts per criterion);
2. reads `app/shots/pieces/*.manifest.json` — both observed schemas (flat
   `output`/`spec`/`name`, and nested `outputs.piece`) — capturing name, spec,
   output PNG, sha256 and manifest mtime;
3. reads `docs/t6/*_LANE.md` ticket tables, whichever column header carries
   "state", and normalises declared states to
   PASS/FAIL/UNVERIFIED/IN_PROGRESS/IDLE/BLOCKED;
4. joins by ticket id (piece-name match, plus an observed manifest
   `generator` ↔ lane owned-files string match) and writes
   `docs/t6/DASHBOARD.md` with summary counts, a generated UTC timestamp,
   one row per known ticket, one row per unmatched manifest, a
   "Reports with no matching lane ticket" section and a parse-anomaly list;
5. refuses to invent PASS: absent report ⇒ `NOT_RUN` / `0/0`, ambiguous
   criterion verdict ⇒ UNVERIFIED, and a lane-declared PASS is demoted when
   the report verdict is UNVERIFIED.
6. CLI: `python app\tools\t6_registry.py` or `--out PATH`; exit 0 on success.
   It backs up an existing output to
   `inbox\backup\DASHBOARD.md.bak-T6-Q01` before overwriting it.
