## 3. Implementation (deterministic, headless)

`python app/tools/pieces/t6_forest_conifer.py` (Python 3.14 + Pillow 12.1.1 +
NumPy 2.4.3). One `random.Random(7*1000003+17)` drives placement; ground uses
the renderer's mirror-tile + wrap-crop + `adjust_bcs(1.0,1.12)` exactly.
Pipeline: tinted forest floor → seeded density field → Poisson-style clumped
placement of 212 trees (weights spruce 0.40 / pinesmall 0.30 / firsmall 0.24 /
dry 0.06; buckets 50 / 35 / 15 %) → per-species RGB grade + upper-crown branch
frosting + near-black floor → soft lower-left contact ellipses → painter's
order by y. `with_trees=False` returns the ground+shadow base for difference
masking. Re-render is byte-identical (SHA-256 below).

## 7. Honest visual judgement (A/B read)

Both final PNGs were opened and compared with the donor crops. The render now
reads as a **dark conifer forest**: 212 layered spruces/pines/firs of three
clearly different sizes, dark near-black crowns interleaved with lime-lit tips,
a uniform olive floor with soft grain, and small soft shadows pooling to the
lower-left of each trunk. The Poisson density field gives obvious clumps and
gaps — no checkerboard, no repeated icon row. Near-black is 0.006 %, so there
are no hard black outlines. This is a genuine improvement over the T2 baseline
(2 trees on a pale tile).

It is still a **2D proxy**, not the donor: the port sprites are narrower and
more see-through than the lush 3D whorled spruces in #11/#7, so canopy closure
and branch-level frosting are only suggested (upper-crown gain + per-tree
brightness jitter), and there is no true ambient occlusion or height channel.
The donor frame also contains troops/terrain relief the piece deliberately
does not model. On the coordinator's stated bar — "real forest, not diagram
art" — the piece passes; on literal pixel-for-pixel donor fidelity it does not.

## 8. Open questions

1. **Q1 — sprite palette state changed since T2.** The T2 audit measured conifer
   lit blue 2–11/255; my fresh probe measures B/G 0.46–0.66 on the *current*
   `sprites_hi/tree_*.png`. Either an intervening rebake or a different lit-pixel
   definition caused this. The grades here are intentionally gentle because of
   it; a manager should confirm which measurement is authoritative before any
   asset-level blue-lift ticket is closed.
2. **Q2 — component segmentation merges crowns.** In a dense canopy, 216 of 260
   connected components are merged fragments or multi-tree blobs, so the
   spec's raw connected-component method cannot recover the 3 buckets. I used
   planned rendered heights (the actual draw sizes) as the primary size measure
   and report the component result openly. A marker-based/watershed segmenter
   would be needed for a stricter component-only verdict.
3. **Q3 — global gate value band.** sat 0.551 (0.001 over) and val 0.207 (below
   0.25). The donor forest floor itself (`#3B3F1B`, sat 0.57, val 0.247) sits
   outside this band, so the gate appears calibrated to mixed bright-terrain
   shots, not a pure dense-forest close-up. I kept donor-matched colour rather
   than washing the forest out to force the gate. Confirm whether the gate
   should apply to this piece.
4. **Q4 — two firsmall variants** (`firsmall2`, `firsmall4`) measure H/W 1.88 vs
   the 1.78 ceiling, inherited from the sprite bank; they remain a minor
   silhouette outlier, not introduced by this baker.
5. **Q5 — shadow margin is thin (1.515 vs 1.50).** It passes deterministically
   but has little headroom; if downstream grading changes the floor brightness,
   `SHADOW_ALPHA` should be revisited.
