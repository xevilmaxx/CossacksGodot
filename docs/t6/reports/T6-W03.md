## 1. Donor truth — what the water reflection actually is (`observed`)

All line numbers below were re-read directly from the donor files this ticket
(verbatim quotes are `observed` *as text*; runtime bindings are separate).

### 1.1 Declarations (`water.dev.frag:1-18`, `water.dev.vert:1-11`)

```glsl
// water.dev.frag:5-6
uniform sampler2D waveMap;
uniform sampler2D reflectionMap;
// water.dev.frag:14 — the ONLY live gain knob on the reflection path
uniform float hdrMultiplier;            // = 1 per water.lib:25 (observed)
// water.dev.frag:8-16 — commented out: NOT live
//uniform vec4 deepColor;  //uniform vec4 shallowColor;
//uniform float reflectionAmount;  //uniform float waterAmount;
//uniform float fresnelPower;  //uniform float fresnelBias;
//uniform float distFactor;  //uniform float bumpFactor;
```

`reflectionMap` is a plain `sampler2D` — **not** a `samplerCube`. The object
environment system is the one that uses `samplerCube`/`textureCube` (`observed`:
`env.smx9.id3.frag:1-2,13-14,22`, `dec.ref.pvl.sm.vert:23`,
`shaders.lib:157-194,1056-1093,1173-1252`; see RENDER_ARCH_REFLECTION §§3.2, 3.4).

### 1.2 Projective UVW (`water.dev.vert:15`)

```glsl
// water.dev.vert:15 (active vertex program per water.lib:67)
gl_TexCoord[0] = gl_TextureMatrix[0] * pos;
```

`observed`: the reflection coordinate is a **projective UVW** built from the
object-space position through texture matrix 0. It is interpolated across the
water surface and consumed with a projective lookup — the signature of a
*live projected 2D texture*, not a cubemap vector lookup.

### 1.3 Wave jitter (`water.dev.frag:192-194`)

```glsl
// water.dev.frag:186-194
vec2 dif = vec2(.0, .01);
vec2 pos = uv*15./texScaleS*(hmapW/128.0) + vec2(iglobaltime*.01); // texScaleS = 0.105 sic
float h1 = water_map(pos-dif,   waveheight);
float h2 = water_map(pos+dif,   waveheight);
float h3 = water_map(pos-dif.yx,waveheight);
float h4 = water_map(pos+dif.yx,waveheight);
vec3 normwater = normalize(vec3(h3-h4, h1-h2, 0.15)); // norm-vector of the 'bumpy' water-plane
vec2 wavejitter = normwater.xy*texScaleT*(level-height); // texScaleT = [0.1..0.0001]
uv += wavejitter;
```

`observed`: `wavejitter` is the water-surface normal's xy, scaled by
`texScaleT` (`= 0.01` per `water.lib:32-33`, `observed`) and by the local water
depth `(level-height)`. It displaces **both** the bed sample (`uv +=`) and the
reflection sample (§1.4). Deeper water jitters more; at the waterline
(`level == height`) jitter is exactly zero (`derived`).

### 1.4 Projected reflection fetch (`water.dev.frag:207-213`)

```glsl
// water.dev.frag:207-213
vec3 refuv = gl_TexCoord[0].xyw;
refuv.xy -= wavejitter*refuv.z;
vec4 refcol = texture2DProj(reflectionMap, refuv);
refcol.xyz *= (refcol.x+refcol.y+refcol.z)*hdrMultiplier;
//vec4 watcol = mix(shallowColor, deepColor, facing)*waterAmount;      // dead
//refcol = mix(watcol, refcol, fresnel)*reflectionAmount;              // dead
watercolor = watercolor + refcol.xyz; //watercolor=mix(refcol.xyz, watercolor, 0.5);
```

`observed` mechanics, step by step:

1. `refuv = gl_TexCoord[0].xyw` — take the projective coordinate (x, y, w).
2. `refuv.xy -= wavejitter*refuv.z` — perspective-correct jitter: the UV offset
   is scaled by `refuv.z` (= the interpolator's w) so the displacement survives
   the projective divide. (`derived`: this is `uv_offset * w`, the standard
   pre-divide form.)
3. `texture2DProj(reflectionMap, refuv)` — sample with implicit divide by w.
4. `refcol.rgb *= (r+g+b) * hdrMultiplier` — **luminance gain**: the fetched
   colour is multiplied by its own Rec.709-approximate luminance sum
   (unweighted `r+g+b` in the donor, *not* 0.2126/0.7152/0.0722 — `observed`)
   times `hdrMultiplier = 1` (`water.lib:25`, `observed`). Bright source pixels
   contribute super-linearly; dark ones nearly vanish (`derived`).
5. `watercolor += refcol.rgb` — **additive**, unmasked by any Fresnel term
   (Fresnel lines are commented out, `observed`). The reflection rides on top of
   the body colour computed at `:198-201` and is then carried through the
   body/glint chain (`*= 2.2+watershade`, corona divisor, spec adds, `:222-226`)
   before `mix(rescolor, watercolor, coastfade)` at `:229` (`observed`).

## 3. Z-order caveat adjudication — R4 §5.2 is still true, head-on

**Prior caveat (R4 §5.2 + R7 §§3–4):** in the shipping 2D overlay a
`hint_screen_texture` sample "would contain only terrain due to z-order".

**Verdict: CONFIRMED against the current code — still true, and the constraint
is tighter than "only terrain".** (`derived` from `observed` code + `observed` docs.)

1. Current draw order (`observed`, `world.gd`): terrain chunks `z=-10` →
   water overlay `z=-9` (`:858`) → resources `1` → buildings `2` → units `3`
   → fx `4` → fog `10`. The overlay's `TEXTURE` mask itself is the baked bed,
   drawn underneath.
2. Back-buffer semantics (`observed`, docs): "when `hint_screen_texture` is
   first found in a node that is about to be drawn, Godot does a full-screen
   copy to a back-buffer **before drawing that node**"; in 2D the copy contains
   exactly what has been drawn so far in tree order.
3. Therefore a `hint_screen_texture` uniform added to `water_overlay.gdshader`
   as-shipped samples **baked terrain + clear colour only**: no resources,
   buildings, units, fx, or fog — and not even the water overlay itself
   (the copy predates its own draw; overlapping readers need `BackBufferCopy`,
   docs §"Behind the scenes", `observed`).
4. Calling that sample a "reflection" overstates it by one full category: at
   best it is **refraction of the substrate** (R7 §4B wording adopted verbatim).
   Near-shore jittered UVs additionally pull land pixels into water pixels
   (edge bleed) with no depth buffer available to reject them in this pure-2D
   scene (F5). Stale-buffer ghosting on camera jumps is a further documented
   risk (R7 §7 "no new screen artefacts" gate).

**What would change the verdict, honestly labelled:**

- Raising the overlay above units/fog (or inserting `BackBufferCopy` nodes
  mid-stack) would put casters *into* the copy — but it also changes composite
  order, translucency sorting, fog-over-water, and the "one quad, no screen
  work" property (`water_overlay.gdshader:10`, `observed`), and risks exactly
  the land-bleed / double-draw artefacts R7 rejects. That is a **scene-tree and
  draw-order change**, i.e. W04 integration work with A/B captures — not a
  shader-uniform one-liner. (`derived`; gated, not proposed here.)
- A `SubViewport` bake (F3) sidesteps z-order entirely: its contents are
  whatever W04 chooses to render into it, independent of main-view draw order.
  That is why the recommended primary uses F3, not F1. (`derived`.)

No hand-waving: **as the tree stands today, `hint_screen_texture` cannot see a
single reflection caster. Any Tier-1 claim built on it would be false.**

## 4. Recommended proposal (design only — W04 builds it)

### 4.0 Primary approach P — offscreen reflection-bake texture (F3), donor-homologous fetch

**One sentence:** keep the shipped single-quad `canvas_item` overlay; add a
*separate* low-rate reflection bake (own `SubViewport` → `ViewportTexture`,
**ordinary `sampler2D` uniform, never `hint_screen_texture`**) whose contents
W04 defines as "what the water should reflect", and fetch it in-shader with the
donor's projected-UV-minus-jitter form, donor luminance gain, and
`hdrMultiplier = 1`, behind a `reflection_enabled` toggle mirroring the donor
`WaterReflection` option.

Why this is primary (`derived`):

- It is the only route that (a) works in Compatibility `canvas_item`, (b) is
  independent of the fatal z-order (§3), (c) reproduces the *observed* donor
  fetch shape (§1.4) instead of the *wrong-system* cubemap, (d) needs no donor
  asset copy and no licence review, (e) keeps the N-07 bake path untouched
  (bind-time/own-viewport work, never `_build_chunk`).
- Cost is controllable: bake at reduced resolution and reduced rate (see limits);
  the per-pixel shader cost is +1 fetch, the cheapest of all live options.

**Bake contents (W04 decision, three honest options in preference order):**

- P-a (recommended): **caster-only bake** — duplicate-free render of the
  above-water reflection casters W04 enumerates (near-shore buildings/units/
  decor silhouettes + a sky-gradient clear colour + sun-corona blob at the
  mapped donor sun direction). Deliberately *not* the whole scene: bed pixels
  must never reflect themselves.
- P-b: **flipped-caster bake** — same as P-a with a vertical flip about the
  local shoreline tangent for near-bank casters (cheap faux-mirror; honest
  label: stylised, not geometric).
- P-c: **sky-gradient-only bake** — a 1D/2D procedural sky + sun blob with no
  scene content. Zero scene-coupling; still gives the donor's bright-source
  super-linear response something to chew on.

Resolution/rate envelope (design targets, W04 measures): bake viewport at
**1/2–1/4 linear resolution** of the main view, refresh at **15–30 Hz or on
camera/anim dirty**, never per-frame full-res; shader-side bilinear fetch hides
the rest under wave jitter. (`inferred` targets; W04 must measure per F11.)

**Uniforms (names are a proposal for W04; types are binding):**

| Uniform | Type | Value / source |
|---|---|---|
| `reflection_tex` | `sampler2D` (`repeat_disable`, `filter_linear`; **no** screen hint) | `ViewportTexture` of the reflection `SubViewport` (F3) |
| `reflection_enabled` | `float` (0.0 / 1.0; mirrors donor `WaterReflection`) | game/video option, default 1.0; 0.0 must be pixel-identical to today's shader |
| `reflection_strength` | `float` (tuning only, default 1.0) | exposure trim for the bake's authored brightness; NOT a donor constant |
| `hdrMultiplier` | `const float = 1.0` | donor `water.lib:25` (`observed`); hardcode, never a slider |
| `texScaleT` | `const float = 0.01` | donor `water.lib:32-33` (`observed`); the jitter scale |
| `SCREEN_PIXEL_SIZE` | built-in | jitter is computed in pixels, converted to screen UV |

### 4.1 Exact shader-side formula homologous to `water.dev.frag:207-213`

Donor (GLSL, `observed`):
`refuv=xyw; refuv.xy-=wavejitter*refuv.z; refcol=texture2DProj(map,refuv);
refcol.rgb*=(r+g+b)*hdrMultiplier; watercolor+=refcol.rgb;`

Port (GDShader `canvas_item`, Compatibility-safe; `wavejitter` already exists as
the donor `normwater.xy*texScaleT*(level-depth)` vector in **mask/UV units** —
W04 converts it once to the bake-UV space; the snippet shows the fetch tail):

```gdshader
// Homologue of water.dev.frag:207-213. reflection_tex is the F3 bake
// (ordinary sampler2D). wavejitter_uv is the donor wavejitter expressed in
// reflection-bake UV units (pixels * bake TEXTURE_PIXEL_SIZE equivalent,
// computed on the W04 side from the existing normwater term).
vec2 ruv = SCREEN_UV - wavejitter_uv * reflection_enabled;
vec3 refcol = texture(reflection_tex, ruv).rgb;
float refluma = refcol.r + refcol.g + refcol.b;   // donor: unweighted sum (:210), NOT Rec.709
refcol *= refluma * 1.0;                          // hdrMultiplier = 1 (water.lib:25)
col += refcol * reflection_strength * reflection_enabled * band_gate;
```

Notes (`derived`, keep faithful):

- `SCREEN_UV - jitter` is the orthographic-2D specialisation of donor
  `refuv.xy -= wavejitter*refuv.z`: with no projective w in `canvas_item`, the
  `*refuv.z` factor is 1 by construction; the subtraction direction (minus) is
  preserved exactly.
- Luminance is the donor's **unweighted** `r+g+b` sum, not the Rec.709 dot used
  elsewhere for the bed (`frag:200`). Do not "fix" this to Rec.709 — the
  super-linear bright-source response is the donor look.
- `band_gate` confines reflection like the body mix: `coastfade`
  (`depth/0.57`) ramp is the honest minimum (still water at the waterline gets
  ~zero reflection, matching `wavejitter → 0` there); W04 may gate additionally
  by `coastfade2`. Additive AFTER the `2.2+watershade` body gain and BEFORE /
  WITH the spec adds, mirroring donor order `:213` → `:222-226` then
  `mix(rescolor, watercolor, coastfade)` `:229`.
- `reflection_enabled = 0` must short-circuit to today's output (A1 control).
  Branch on the uniform, not on `#ifdef`, so the A/B toggle is runtime-clean.

### 4.3 Explicit LIMITS — what cannot be reproduced, cost, caveats, licence

1. **No true geometric mirror.** Top-down 2D has no below-plane geometry; P-a/P-b
   are authored proxies. A pixel-perfect donor-planar-FBO match is unachievable
   in this scene graph — and since U1 is UNVERIFIED, "pixel-perfect vs FBO"
   is not even a defined target. (`derived`.)
2. **No Fresnel, no `WaterAmount`/`ReflectionAmount`.** Commented out in the
   donor (`observed` §1.1); do not invent them. The add is unmasked by design.
3. **Donor `refuv.z` perspective term has no 2D counterpart.** Specialised to 1
   (§4.1). Any future perspective camera invalidates this mapping. (`derived`.)
4. **Donor shadow-on-water (`test_shadow`, `watershade`) is out of scope** for
   the reflection proxy; body gain stays `2.2 + 0` as today (`observed` R8:123).
5. **Cost (`inferred`, W04 must measure):** +1 bake-viewport render at reduced
   rate/res (P) + 1 screen-independent fetch/px + ~4 ALU/px. No full-screen copy
   (unlike F1/F11). Bake work must live **outside `_build_chunk`** (N-07 guard);
   any regression of `BAKE_BENCH max_ms` vs baseline fails A3 even if water
   looks better.
6. **Compatibility caveats (`observed` docs):** overlapping `hint_screen_texture`
   readers need `BackBufferCopy` (F1 only); region-mode misreads are undefined;
   mipmap-blur screen sampling has renderer-specific artefacts (F1 only — P
   uses explicit bake mipmaps instead); `samplerCubeArray`/normal-roughness are
   unavailable (irrelevant here, F4/F6).
7. **Licence/provenance:** P/F1/F2 need **no donor asset, no conversion, no
   review**. F3 (cubemap) needs a conversion tool + licence review before any
   shipping/distribution (R4 §5.1, R7 §9.4). This ticket copied nothing; W04
   must keep it that way (A5).
