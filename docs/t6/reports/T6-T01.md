**Renderer defect found (observed):** `terrain_piece_render._render_patches`
feeds signed grid values through `_smooth_field`, which writes them into an
`L` image; every negative value clamps to 0 (seed 7, 26×26 grid: field mean
**62.57** instead of 128). With gain 80 the olive gain is biased by **−38.6 L**
(channel shifts −41.0/−39.4/−27.9). The old `grass_mottled.png` therefore got
its std from a mostly-negative gain plus a bright tail, not a symmetric
terrain-driven ±L driver. This mini-baker keeps the gain as a NumPy float array.

## 4. `grid_peak` metric definition (derived — needed because the phrase is ambiguous)

T4-BLEND defines it as `0.5*(|ACF(0,cell)|+|ACF(cell,0)|)/ACF(0,0)` at one
cell lag (`terrain_blend_test.py:347-366`). Applied raw to a 200² mottled-grass
crop the donor itself scores 0.26–0.25 (its smooth tonal ramp dominates ACF),
so raw ACF cannot be the intended "coarse blotch" gate. I therefore **high-pass
detrend** with `L − GaussianBlur(6)` before the same FFT autocorrelogram and
take the max over patch-scale lags 8–40 px. Calibration is in §1: donor 0.048 /
0.025 / 0.066, old baseline 0.203 (fails), synthetic checker 0.93 (fails).
This is a **derived interpretation**, recorded as an open question for the
parent to ratify.

## 5. Visual judgement (decisive — metrics did not override it)

I read every candidate PNG with the image-read tool, not only its metrics.
- CDF **centre** mapping (`ramp`-off) measured well (L1 3.6) but produced a
  **posterised camouflage pattern** → rejected on visual grounds.
- Continuous **noise** mode looked natural but scored grid_peak 0.43 and L1 60 → rejected.
- Continuous **ramp** CDF with the un-censored donor histogram scored 11/11
  metrics but showed **fire-yellow blobs** (bins 5–7 from the donor's explosions) → rejected visually.
- A fire-censored "smalltail" variant passed all gates, but on **parent visual
  review (T6-TERRAIN, 2026-11-23)** the port side still read as "large blurry
  camouflage blobs (~40–80 px)". I accepted the valid part of that criticism
  and reworked the texture (see below).
- **Rework (final):** added octaves at cell/2 (w 0.20) and cell/4 (w 0.08) to
  the smooth driver so tonal patch edges are ragged rather than BICUBIC-round,
  and raised the additive fine grain from 4 → 6 L so hi-freq rises 8.06 →
  **10.58** (donor relief 11.18) and the texture competes with the patch tone.
  `cdf_tighten` was lowered 0.85 → 0.82 to keep histogram L1 ≤25. After the
  rework all 11 gates still pass. **Visual verdict: PASS with caveats** —
  grain is visibly finer and patch edges are less blobby; a few bright
  sunlit-tip specks (~1.8% pixels) remain slightly more yellow than donor
  grass, and broad tonal regions remain because C1 (std 30–40) *requires*
  them. A 2-D noise proxy cannot reproduce actual grass-blade geometry.

**Distinction from the clean-grass crop (honest scope note).** The parent
compared against #8 clean grass (std 8.6 / hi-freq 2.96 / 2–5 px speckle).
That is the `grass_clean` negative control, not this piece: `grass_mottled.md`
lines 10, 52, 159 and 168 require std 30–40, ~4× clean, and explicitly call
std <12 / 2 bins / hi-freq ~5 the "gain driver dropped → collapsed into
grass_clean" **failure signature**. Matching the clean crop would therefore
be a regression, not a fix. The valid part of the feedback — soft blobs
instead of textured patches — was fixed without crossing that boundary.

panels: render | donor #6 spec crop | donor #8 PRIMARY grass crop. The donor
panels are read-only reference crops; no donor binary is embedded in the repo.

   <0.20 gate and discriminates donor/checker correctly, but T6_WAVE_PLAN does
   not state the detrend. Parent should ratify (or supply the canonical script).

   Possibly the gully-mixed crop (4 bins) was intended. Needs owner wording.

   C1/C8 are calibrated from that contaminated vector. I used a fire-censored
   target and still passed L1 (19.7 / 17.9). Confirm that censoring is the
   intended pure-grass interpretation; if not, accept the brighter variant
   (which measured 11/11 but looked like fire).
4. **Shared-renderer fix** — `_render_patches` negative-value clamp is a real
   defect affecting other pieces with signed grids (e.g. plateau/winter
   patches). Integration ticket recommended; I did not edit the shared file.
5. **Port driver** — the exact donor bitmap that drove the 20–80 px gain is
   still unknown (`tile_low/highground` R÷2 is per-cell); my multi-octave value
   noise is a documented INFERRED proxy, not a donor reconstruction.
