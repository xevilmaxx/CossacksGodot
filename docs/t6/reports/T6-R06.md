## Implementation summary

| File | Role |
|---|---|
| `rustport/src/raster/framebuffer.rs` | `Vec<u32>` **RGBA8 framebuffer (R in LSB, `0xAABBGGRR`)** + `Vec<f32>` depth; `put_pixel`, `put_pixel_depth`, `clear`, `blit`, `get_pixel(s)`, `to_rgba_bytes`. Barycentric edge-function rasterizer with pixel-centre sampling `(x+0.5,y+0.5)`, normalised winding, **top-left rule**, strict `<` depth test. Solid, gradient and textured triangle fills. |
| `rustport/src/raster/terrain.rs` | Seeded 16×16 tile grid (64 px/tile → 1024×1024); 8 curated donor blocks from §3.2 families (grass, grass_ground, grass_sand, ground, rock, sandsea, sandrock); `splitmix64` block/crop assignment; height field + central-difference normal + Lambert diffuse shade. Each tile = two real textured triangles through the rasterizer. |
| `rustport/src/raster/sha256.rs` | std-only SHA-256 (FIPS 180-4) + hex; FIPS `sha256("abc")` self-check in the test. |
| `rustport/src/raster/output.rs` | Writes `raster_piece.{raw,png}` into `rustport/shots/`, prints paths + SHA-256, runs Pillow converter; luminance/variance helpers. |
| `rustport/src/bin/raster_piece.rs` | Demo binary (Cargo auto-discovered), produces the final deterministic shot. |
| `rustport/tests/raster_piece.rs` | 4 acceptance tests. |
| `rustport/tests/tools/raw_to_png.py` | Pillow raw→PNG converter. |

**Documented lighting.** Height `h(x,y) = 0.012x − 0.008y + 9·sin(0.011x+p1)·cos(0.013y+p2) + 4·sin(0.027(x+y)+0.5p1)` (p1,p2 seed-derived). Normal `N = normalize((−2.5·∂h/∂x, −2.5·∂h/∂y, 1))` via central differences. Light `L = (−0.5, −0.5, 0.70710678)` (unit, screen-space upper-left/above). Shade `= 0.30 + 0.85·max(0, N·L)`, clamped to `[0,1.5]` and multiplied per RGB channel. `shade_enabled=false` is the flat baseline.

**Module-inclusion note.** `src/raster/mod.rs` was deliberately **not** created: `src/raster.rs` already exists, so a `mod.rs` would trigger E0761 ("file for module `raster` found at both"). Instead the bin/test use explicit `#[path = "../raster/xxx.rs"] mod xxx;` as the ticket allows.

## Open questions / handoff to T6-RUST and integration

1. **Wiring into the library.** `src/raster.rs` is owned by integration and was left untouched. The implementation is in `src/raster/*.rs` and currently compiled via explicit `#[path]` in the bin/test. Integration should decide whether to replace the stub with `#[path = "raster/framebuffer.rs"] mod framebuffer; ...` re-exports, or keep the explicit-include pattern. Creating `src/raster/mod.rs` is **not** an option while `src/raster.rs` exists without editing the stub.
2. **R07 visual A/B.** This ticket did not compare against a donor reference map (out of scope, piece-before-whole). The height function and block family mix are a plausible stand-in, not a calibrated donor match; donor-derived tuning belongs to the R07 gate.
3. **Shading realism.** Diffuse Lambert with a fixed height field; no self-shadowing, no normal-map from donor, no per-tile seam blending. Acceptable for the piece gate; flag if R07 needs seam smoothing.
4. **Perf.** Debug build renders 4 full frames (determinism ×2, shaded, flat) plus 32 donor-block decodes in ~10 s; release/integration perf was not measured here.
5. **Warnings.** Non-fatal `dead_code` warnings come from API methods required by the ticket but not exercised in every target, plus the read-only R05 `DdsImage.format` field. No change made to read-only R05 files.
