## 3. Exact diff (`variant3d/scripts/world3d.gd`, final line numbers)

## 4. Measured ms

Temp probe `variant3d/tests/t_v780_res_dirty_gate_probe_tmp.gd` (SceneTree,
200 unit dicts + 1200 resource dicts, stub `entities` recorder so only the scan
is timed), 3 rounds × 120 reconciles, median reported. "Before" forces a
`res_dirty` bump each reconcile — functionally the pre-V7-80 always-scan path.
"After" leaves `res_dirty` unchanged so the gate is closed (the entity half
still runs). Full raw data in ticket 197 stdout / result JSON (both the probe
source and JSON were deleted after the run, per the brief).

| State | Samples (ms/frame) | Median (ms/frame) |
|---|---|---|
| Before — dirty bumped every frame (always scan) | 5.244 / 4.179 / 3.825 | **4.179** |
| After — dirty unchanged (gate closed, entity half still runs) | 0.363 / 0.333 / 0.327 | **0.333** |

- **Total reconcile: 4.18 → 0.33 ms = 12.54× faster** at 200 units + 1200
  res_nodes; ~3.85 ms/frame of resource-scan work removed.
- Cross-check: PERF3D_sync_hotpath.md §0/§3 measured 3.92 ms at the same shape
  with a real `C3Game`; the stub's 4.18 ms is the same order, so the gate targets
  the measured hot path. At 200 units with no resources the cost is already
  ~0.42 ms (PERF3D), which is what the gated path approximates here (0.33 ms).
- This is a **CPU scan** saving only. No visual/GPU parity is claimed.

## 6. Open questions

1. **`fields_live` / `moved` not copied.** `app/scripts/world.gd:2102` also
   force-redraws while `game.fields_anim` is true or the camera moved; those are
   redraw-only clauses (growth bars / rotors, `world.gd:2096-2098`) with no
   counterpart in an add/remove feed, and field completion bumps `res_dirty`
   (`game.gd:2170`). **UNVERIFIED** whether a future 3D *visual* growth animation
   will need a per-frame gate-open; if it lands, add the clause there rather
   than pre-emptively here.
2. **Silent in-place `hits` transitions.** `game.gd:522-528` (`_clear_area`)
   zeroes `hits` without bumping `res_dirty` or changing size. Until the next
   dirty bump/size change, the gated feed will not issue `remove()` for such a
   node. This is the *same* blind spot 2D already has in `_res_grid_ensure`
   (`game.gd:2642-2661`), so it is preserved, not introduced. The PERF3D report's
   "forced rescan every ~30 frames" idea (§4 item 3) was **not** implemented,
   per "translate, do not invent"; it remains an open design question if a
   3D-only correctness requirement appears.
3. **Absolute ms on a live generated map.** The probe uses a Dictionary double;
   a real windowed run with a populated forest may differ with machine load and
   renderer backend. Only the ratio between the two probe states is claimed as
   measured here.
4. **Visual parity:** not tested and not claimed (headless, stub recorder).
